# Receipt Divider for iOS

This native iPhone reference client is written in SwiftUI and targets iOS 26 or later.

For automatic builds and wireless iPhone installation after pushes to `main`, see [Wireless deployment](WIRELESS_DEPLOYMENT.md).

Use `TabView`, `NavigationStack`, toolbars, sheets, and standard buttons. Do not recreate Liquid Glass with custom materials or blur layers: current iOS automatically gives standard components its system treatment.

On a Mac, install [XcodeGen](https://github.com/yonaskolb/XcodeGen), copy `Signing.local.xcconfig.example` to `Signing.local.xcconfig` and set your Apple Developer team ID (the copy is gitignored), run `xcodegen generate` in this folder, and open `ReceiptDivider.xcodeproj` in the newest Xcode. Xcode resolves the Supabase Swift package within the 2.x release line. Test on a current iPhone to validate authentication, Sign in with Apple, and the system Liquid Glass behavior.

Run the tests on a simulator with `xcodebuild -project ReceiptDivider.xcodeproj -scheme ReceiptDivider -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test`. They cover the adjustment math, item ownership, and the fallback parser. `ReceiptModelFixtureTests` runs the on-device model on sample receipt text when Apple Intelligence is available (it is skipped otherwise) and logs known gaps as expected failures.

The app opens through a custom SwiftUI authentication gate. Email and password is the primary sign-in/create-account method, with iOS Password AutoFill, emailed password reset, and native Sign in with Apple. New accounts also collect real first name, real last name, and a unique username. Supabase restores and refreshes a saved device session automatically; Settings provides sign out. Once authenticated, the app provisions the account profile, loads the canonical ledger from the deployed Edge Function, and posts expenses, optional receipt evidence, repayments, and friend requests with the current access token. An account-scoped device cache supports display continuity, but Supabase is canonical. Camera/photo intake, document cropping, and text recognition run on the device. Receipts are read first by the backend cloud vision endpoint (`POST /v1/receipts/parse`, OpenAI `gpt-6.1-sol` with structured output) through `CloudReader`, which starts with the photo. It returns the printed rows, each with its text, price, and label (`APIReceiptReading`), which become `ReceiptRow`s and `ReceiptLabels` and go through the same `ReceiptExtraction(rows:labels:text:)`, checks, re-read, and diagnostics as the on-device model; when it fails or finds no items, the on-device reader below takes over. `RecognizeDocumentsRequest` and the accurate `VNRecognizeTextRequest` pass recognize the text, merged by `ReceiptTextRecognizer.merge`; `layoutRows` groups it into printed rows and `ReceiptRow` takes each row's price from its right end. `ReceiptReader` (`ReceiptExtraction.swift`) has the Foundation Models model label the priced rows (`ReceiptLabels`) while participants are chosen, and falls back to the rule-based parser when Apple Intelligence is unavailable. `ReceiptReplayTests` replays real receipts from saved diagnostics. Each scan's `ReceiptDiagnostics` (lines with positions, model attempts with raw output and timing, reader, and read vs. saved values) is uploaded with the receipt text and stored in `evidence_assets.extracted_data`; the deploy script stamps the commit into the app, and developer accounts see it with the last scan's reader and time in Settings. `ReceiptAdjustments.swift` holds the deterministic math: quantity rows, and ordered discounts, taxes, tip, and surcharges that set each item's global offset.

## Supabase setup

1. Create a Supabase project and enable Email and Apple under Authentication providers.
2. Turn off Authentication → Sign In / Providers → Email → Confirm email so account creation immediately returns a session, and add `receiptdivider://reset-password` under Authentication → URL Configuration → Redirect URLs.
3. The current project URL, publishable client key, and Supabase Edge Function base URL are configured in `project.yml`. Never place a database URL or Supabase secret/service-role key in the app; update only the client-safe values there if the project changes.
4. In the Apple Developer portal, enable Sign in with Apple for `com.receiptdivider.app`. Configure that bundle identifier as an accepted Apple client ID in Supabase.
5. Regenerate the Xcode project after changing `project.yml`.
6. Deploy `supabase/functions/ledger-api`; the app will send its restored Supabase access token to that function for every protected ledger request.

## Live ledger integration

- `LedgerAPIClient.swift` owns authenticated HTTP requests to the Edge Function configured by `API_BASE_URL`.
- Authenticated launch upserts the profile and replaces the displayed ledger with the server snapshot. Summary reloads it whenever it appears and on pull to refresh, so expenses friends add that include you show up.
- Everyone in the ledger is an app account identified by user ID (`LedgerPerson`). The split flow offers you plus your accepted friends; Summary shows your overall balance and your balance with each person.
- Saving an expense inserts it into local history and balances immediately, identified by its client request ID, while its optional JPEG evidence and idempotent expense command upload. A later snapshot replaces that pending row with the canonical database expense without duplication. Recording a payment remains server-first.
- New account entry collects real first name, real last name, a unique username, and private authentication email. Profile editing groups the three identity fields and provides a draggable, pinch-to-zoom circular crop before a new profile photo uploads. Profile presents a system Liquid Glass Friends control on current iOS, with a bordered fallback on older supported releases.
- Friends supports searching by name or username, invitations, incoming acceptance, pending requests, accepted lists with profile photos, and press-and-hold to remove a friend. The open screen refreshes every 5 seconds.
- Settings keeps the device preference for participant self-reference. Vertical and horizontal scroll indicators are hidden globally across the application. Assign Items is encapsulated in portable `AssignItemsView` with top content margin matching review, fixed-height item rows, and a bottom selector with All followed by an icon/first-name pill for every selected participant (five filters fit across before scrolling, and fewer than five filters are centered). When accessed from Review expense, assigning rows opens with items initially unassigned and tapping the checkmark returns back to review with updated shares, while Back returns to review.
- Select participants is dedicated to choosing split members on a unified component combining a compact rounded search bar with an internally scrollable friends list sorted by recency that expands vertically to reach the top and bottom of the page. The top-right confirmation action is a checkmark icon that advances directly to Review expense with all items split evenly by default across participants. Final review is encapsulated in `ExpenseReviewEditorView`, positioning the compact category icon and naming at the top, followed by a vertically compact addition table (labeled Subtotal on left, conditional non-zero tax and tip rows, a distinct thicker summation divider, and total amount with decimal keypad number editing; Total is unlabeled when additive rows exist, but labeled 'Total' when only a single total is present), a grouped payer and date section with matched row heights, and a merged component uniting contribution sliders with the Assign items action at the bottom. Tapping the description card on an existing expense routes directly to this component populated with all fields. The bottom navigation bar's Add expense tab supports a secondary-press or double-tap shortcut that launches the document camera directly with haptic feedback, while a single tap displays all capture options.
- Contribution sliders default to percent and show the dollar equivalent inline in parentheses; choosing dollars reverses that presentation. Expense detail places the participant ownership section above the receipt photo, displaying assigned items indented underneath each person (or combining all names on one line when split evenly). Balance rows use first-name relationship sentences and open Settle Up directly, which showcases specific items owed and owing categorized by context.

Editing or voiding transactions, saved-group filters in the UI, and account deletion remain to be implemented.
